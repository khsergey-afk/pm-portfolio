# План-график и расписание

*EN: How to build a schedule that computes instead of being drawn: WBS of deliverables,
finish-to-start links by default, three-point estimates, contingency in reserves — and the checks
that keep the critical path honest. Based on the PMBOK Guide (schedule management), ISO 21502 and
MS Project practice.*

## Суть

Как построить план-график, «который считается, а не рисуется». ИСР (WBS) — декомпозиция результатов,
а не действий; нижний уровень — пакет работ на 1–10 дней с одним ответственным. Связи по умолчанию
ОН (окончание–начало). Длительности — по аналогам или трёхточечная оценка (O + 4M + P) / 6;
неопределённость — в резерв, а не в каждую работу. Контроль — критический путь без отрицательного
резерва и фиксированный базовый план.

## Порядок

1. **ИСР (WBS)** — декомпозиция результатов, а не действий; нижний уровень — пакет работ на 1–10 дней
   с одним ответственным.
2. **Вехи** — ключевые решения и результаты (нулевая длительность); отдельно — вехи для руководства.
3. **Связи** — по умолчанию ОН (окончание–начало); НН и ОО — с объяснением; у каждой работы есть
   предшественник и последователь.
4. **Длительности** — оценка по аналогам или трёхточечная (O + 4M + P) / 6; неопределённость — в резерв.
5. **Ресурсы** — ответственный у каждой работы; проверка перегрузки.
6. **Ограничения** — жёсткие даты только там, где они есть на самом деле (решение управляющего комитета,
   законный срок).
7. **Критический путь и резерв** — проверить, что КП проходит через ожидаемые работы; отрицательного
   резерва нет.
8. **Базовый план** — сохранить после согласования; дальше — факт на дату отчёта и отклонения.

## Проверки перед выдачей

базовый план есть · нет висящих работ · нет ручного планирования · нет отрицательного резерва ·
праздники в календаре · ресурсы не перегружены · вехи отмечены
