# SLA и OLA — уровни сервиса

*EN: How to describe a service and its indicators so they can be measured and billed: the SLA/OLA/UC
chain, an 8-field indicator card, and the rules that keep a service level agreement dispute-proof.
Based on ITIL 4 and ISO/IEC 20000-1.*

## Суть

Как описать услугу и её показатели так, чтобы их можно было измерить и оплатить. Основа — ITIL 4
и ISO/IEC 20000-1.

## Термины

| Термин | Что это |
|---|---|
| **SLA** | соглашение об уровне сервиса с потребителем услуги |
| **OLA** | соглашение между подразделениями внутри поставщика услуги |
| **UC** (underpinning contract) | договор с внешним подрядчиком, поддерживающий SLA |

Показатели OLA и UC должны быть не хуже SLA — иначе SLA невыполним.

## Карточка показателя

| Поле | Что фиксируется |
|---|---|
| Название | короткое имя показателя |
| Определение и формула | как считается, включая числитель и знаменатель |
| Целевое / пороговое значение | например 95 % / 90 % |
| Период и окно измерения | месяц; рабочие часы 9–18 |
| Источник данных | система, из которой снимается показатель |
| Исключения | например обращения, ожидающие ответа заявителя |
| Ответственный за измерение | владелец услуги |
| Последствия недостижения | план корректирующих мер, снижение оплаты |

## Правила

1. Показатель измеряется из системы автоматически, а не опросом исполнителей.
2. Не больше 3–5 показателей на услугу: срок, качество (доля без возвратов), доступность,
   удовлетворённость.
3. Базовое значение снять до подписания SLA (замер 2–3 месяца), иначе цель «с потолка».
4. Исключения и часы работы записаны явно — главный источник споров.
