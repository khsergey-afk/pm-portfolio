# Gap-анализ (AS-IS → TO-BE)

*EN: How to compare the current and target state across identical dimensions so the output is a
list of changes with owners — not a feeling. Based on BABOK v3 (strategy analysis) and TOGAF ADM
(gap analysis).*

## Суть

Сравнение текущего и целевого состояния по одинаковым измерениям, чтобы получить список изменений
с владельцами. Разрыв фиксируется конкретным отличием с числом; причина — корневая («5 почему»),
иначе решение лечит симптом. Разрывы группируются в пакеты работ → дорожную карту; для каждого
пакета задаётся метрика эффекта.

## Измерения сравнения

Процессы · организация и роли · данные · ИТ-системы и интеграции · нормативные документы ·
метрики и уровни сервиса.

## Правила

1. AS-IS и TO-BE — на одном уровне детализации и в одних единицах.
2. Разрыв — не «плохо/хорошо», а конкретное отличие; одно решение может закрывать несколько разрывов.
3. Причина — корневая («5 почему»).
4. Разрывы → пакеты работ → дорожная карта.
5. Для каждого пакета — метрика эффекта.
